Lab 7: Recursive StackSum and PowerStack

20 points · Unit 5 · Due Sunday, October 18, 11:59 PM

This lab sits in Unit 5 rather than Unit 3 for one reason: you are using a stack to learn about the stack. Every recursive call you make pushes a frame onto the call stack while you manipulate a stack you built yourself. Holding both in your head at once is the point.

StackSum has a postcondition that makes it interesting: the stack must be unchanged when it returns. You cannot look at the buried items without removing them, so the work happens on the way back up the recursion, not on the way down. That is the distinction Shaffer §4.2.4 is about.

Specification

Implement two member functions on StackType.

a) A function that recursively sums the items (stored as integers) of a stack:

int StackSum()

Function: Returns the sum of the integers stored in the stack.
Precondition: The stack contains items (integers).
Postcondition: The stack remains unchanged.

b) A function that updates each integer item so that it becomes its own value raised to the power of the value of the item below it. The top of the stack is used as the item below the bottom item:

void PowerStack()

Function: Each item is replaced with its value raised to the power of the value of the item below it. The bottom item is raised to the power of the item at the top.
Precondition: The stack contains at least two items.
Postcondition: The stack items are updated accordingly.

Worked example (top of stack listed first):

Before PowerStack:        After PowerStack:
      2                         32          2^5  = 32
      5                         125         5^3  = 125
      3                         81          3^4  = 81
      4                         4096        4^6  = 4096
      6                         36          6^2  = 36   (bottom wraps to top)

Implement both functions using the templated linked and the templated dynamic array-based versions of StackType.

Be Ready to Answer

This lab has no Mini Oral. Question 1 is submitted in writing with your code and is graded under Design and Documentation; the rest are not submitted, but all of them are fair game in your Major Oral Inquiry.

Every question below is about your submission. You may use AI to prepare — that is encouraged — but the answers must describe the code you actually wrote.

  1. State the invariant your StackSum recursion maintains about the stack at each level of the call. Write this as a comment above the function.
  2. Trace your StackSum on a three-item stack. What does the stack contain at the deepest call, and what is on the call stack at that moment?
  3. Run PowerStack on the worked example above and show your output. If any value differs, say which and why — overflow is a legitimate answer if you can demonstrate it.
  4. How deep does your recursion go for a stack of n items? At roughly what n would you expect a stack overflow, and what would you do about it in production code?
  5. The precondition for PowerStack says at least two items. Call it on a one-item stack anyway. What happened?
